Octave in your editor: devtools.lsp

Guide · 23 September 2026

devtools.lsp is a language server: it gives any editor that speaks the Language Server Protocol hover, go to definition, document symbols, workspace symbols and completion for Octave code. The server is an Octave interpreter, so what it tells you is what your Octave, with your packages, would itself say. It evaluates no code, runs no user function, and writes nothing.

What you get

FeatureWhat it answers
Hoverthe help of the name under the cursor, as help renders it
Go to definitionthe file and line that define it
Document symbolsthe outline of a file: its class, properties, methods and functions
Workspace symbolsthe functions, classes and methods of the project, found by part of their name
Completionfunction, keyword and project names; a namespace's contents after its name and a dot; a class's methods and properties after an object and a dot

Install

You need GNU Octave 11.1.0 or later and a C++ compiler: the server reads your code through a parser that is built when the package is installed. The language server is not in a release yet, so install the development version, at the Octave prompt:

pkg install "https://github.com/pr0m1th3as/octave-devtools/archive/refs/heads/main.zip"

Check that it is there:

pkg load devtools
which devtools.lsp

The command your editor runs

octave-cli -q --no-init-file --eval "pkg load devtools; devtools.lsp ()"

Do not shorten it. The server talks to the editor over standard output, and --no-init-file keeps anything your ~/.octaverc prints off that stream. On Windows, name octave-cli.exe in full.

Load the packages your project uses. The server sees the packages its command loads and no others, so hover on a statistics function finds nothing unless you name it:

--eval "pkg load devtools statistics datatypes; devtools.lsp ()"

Kate

Tested with Kate 25.04.

  1. In Settings → Configure Kate → Plugins, enable LSP Client.
  2. On the new LSP Client page, open User Server Settings and add:
{
  "servers": {
    "octave": {
      "command": ["octave-cli", "-q", "--no-init-file", "--eval",
                  "pkg load devtools statistics datatypes; devtools.lsp ()"],
      "rootIndicationFileNames": ["DESCRIPTION", ".git"],
      "highlightingModeRegex": "^(Octave|Matlab)$"
    }
  }
}

Kate may take a .m file for Objective-C, which uses the same extension, and start the Objective-C server instead; its Output view then complains that clangd is missing. Set the file's highlighting with Tools → Highlighting → Scientific → Octave. To make that permanent, open Settings → Configure Kate → Open/Save → Modes & Filetypes, choose Scientific/Octave, make sure its extensions include *.m, and give it a higher priority than Objective-C.

Kate starts one server per project, the folder holding DESCRIPTION or .git. The Output view shows the server's own messages; devtools.lsp: listening means it started.

Neovim and Emacs

Neovim 0.11 and later, in init.lua:

vim.lsp.config ('octave', {
  cmd = {'octave-cli', '-q', '--no-init-file', '--eval',
         'pkg load devtools; devtools.lsp ()'},
  filetypes = {'octave', 'matlab'},
  root_markers = {'DESCRIPTION', '.git'},
})
vim.lsp.enable ('octave')

Emacs with Eglot, in init.el. The first line stops Emacs taking a .m file for Objective-C:

(add-to-list 'auto-mode-alist '("\\.m\\'" . octave-mode))
(with-eval-after-load 'eglot
  (add-to-list 'eglot-server-programs
               '(octave-mode . ("octave-cli" "-q" "--no-init-file" "--eval"
                                "pkg load devtools; devtools.lsp ()"))))

How it finds things

Your project comes first

The folder your editor opens is the project. Its functions and classes are read from its files and never put on the load path, since adding a folder to the path runs its PKG_ADD. Where your project and a loaded package define the same name, you get the project's definition. That is what you want while developing a package that is also installed: the installed copy is the stale one.

Within a file, a local function is found before anything else, as Octave itself does.

Methods: certain, or listed

Many classes define methods with the same name: the statistics classes define predict more than forty times. Which one a call reaches depends on the class of the object, which Octave only knows when the code runs. The server answers a method only where the class is certain from the code itself:

  • a call written with the class, Class.method (...);
  • a method or property used on the object of the method you are editing: predict (obj, X) or obj.X inside a method whose first parameter is obj, or inside a constructor on the object it returns.

Elsewhere, hover lists every definition and go to definition offers each one, rather than guessing. For the same reason there are no diagnostics and no rename: both need the meaning of every name, which in Octave is settled only at run time.

If something does not work

  • Nothing happens at all. Check that the editor started the server: in Kate, the Output view should show devtools.lsp: listening. If it shows another server, the file type is wrong; see the Kate section above.
  • A package's functions are not found. Add the package to pkg load in the command.
  • Hover, definition and symbols all fail. The package was probably installed without a compiler, so the parser was not built. The server's log says so. Install a C++ compiler and install the package again.
  • Warnings when the server starts, such as a package reporting that it shadows a core function, come from that package's own PKG_ADD and go to the log. They are harmless.

How to set up and use each part of the package. The reference for every function is under Documentation.

Servers

Octave in your AI assistant: devtools.mcp

The read-only Model Context Protocol server, so that an assistant asks your Octave what exists instead of guessing. Setup, the packages it sees, and checking it with devtools.selftest.

Letting an assistant run Octave: devtools.mcpEval

The evaluating server for an AI assistant: workspaces, the deadline, and what contains it and what does not.

Octave for your spreadsheet and other programs: sandbox mode

How LibreOffice Calc, or any other program, runs Octave functions on outside data in a sandbox: what it can reach, the Calc settings that control it, and octave_call for developers.

Octave in your editor: devtools.lsp

The language server: hover, go to definition, symbols and completion in Kate, Neovim or Emacs, and how it decides which definition a name means.

Package checks

Checking a package's documentation: devtools.docLint

The documentation defects no test can reach: wrong names, broken cross-references, wrong headings, overlong lines and INDEX mismatches.

Which language is this file in? devtools.dialectLint

Whether a package is written in Octave's own dialect, and whether a file will run on MATLAB before you send it there.

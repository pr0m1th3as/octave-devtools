Checking a package's documentation: devtools.docLint

Guide · 23 September 2026

Documentation is the one part of a package that never runs, so no test reaches it. A function that was renamed, a cross-reference to something removed, a line that grew past the margin: all of them survive every test the package has. devtools.docLint checks a package's texinfo against the code it describes, and reports what it can find mechanically.

Run it

Give it the folder a package's source is in, or the name of an installed package:

pkg load devtools
devtools.docLint ('/home/me/src/csg-toolkit')
devtools.docLint ('statistics')

It prints what it finds, grouped by file, with a count per rule at the end. A real run over a package:

INDEX
      -  index-unlisted  does not list 'efd'.
inst/LongBone.m
     18  category        heading is 'Class'; expected 'csg-toolkit'.
inst/simple_polygon3D.m
     17  deftypefn-name  documents 'polygon3D' above function 'simple_polygon3D'.
     18  deftypefn-name  documents 'polygon3D' above function 'simple_polygon3D'.
     19  deftypefn-name  documents 'polygon3D' above function 'simple_polygon3D'.
     20  deftypefn-name  documents 'polygon3D' above function 'simple_polygon3D'.

  category        1
  deftypefn-name  4
  index-unlisted  1
  total           6 in 3 files

With an output argument it prints nothing and returns the findings, one element each, with file, line, rule and message:

R = devtools.docLint ('statistics');
R(strcmp ({R.rule}, 'seealso-target'))

What it checks

RuleReports
deftypefn-namea header naming something other than the function that follows it, or a function file documenting a name other than its own
categorya heading, the first brace group of a header, that is not what it should be (below)
seealso-targetan @seealso naming something that is not in the package, not in core and not in any package now loaded
seealso-memberan @seealso naming a class member without its class: help finds ClassificationTree.margin and does not find margin
widtha texinfo body line longer than 80 columns; header lines are exempt, their signatures being allowed to run over, and so is a line holding a URL alone, which has nowhere to break
index-missingINDEX listing a name the package does not supply, which breaks a documentation build
index-unlisteda function or class the package supplies that INDEX does not list

The heading convention

The heading is what help prints before a signature. The rule expects:

  • the package name from DESCRIPTION for a function, for the block documenting a class, and for the constructor of an old-style @class;
  • the class name, in full, for a classdef constructor, a method and a property: {prob.BetaDistribution}, never {BetaDistribution};
  • never a namespace: a class in +datatypes/+tabular is headed {datatypes}.

A private helper is headed {Private Function} and is not checked against either.

Not every finding is a defect

index-unlisted exists so that what INDEX leaves out is left out on purpose. INDEX decides what is cached and published, so omitting a name is how you keep it off both; if the omission is deliberate, the finding simply confirms it.

What it skips, and what it needs

  • Folders named private, tests and demos, none of which are a package's documented surface.
  • Names wrapped in double underscores are internal, so index-unlisted does not report them; every other rule checks them, since help reads them like any other.
  • A cross-reference is resolved against what is on the load path when you run it, so load the package's dependencies first. Otherwise references into them are reported as unresolved.
  • A compiled function is found by its DEFUN_DLD in a .cc or .cpp file under src, not by the file's name, so a helper source is not taken for a function.

It reads files only and needs no compiler.

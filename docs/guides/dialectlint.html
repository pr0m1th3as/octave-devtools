Which language is this file in? devtools.dialectLint

Guide · 23 September 2026

Octave reads MATLAB's spellings as well as its own, so a file can mix # and %, ! and ~, endif and end, and Octave will never complain. devtools.dialectLint answers two questions Octave will not: is this file written in Octave's own dialect, and would MATLAB accept it?

Is it Octave's own dialect?

Give it a file, the folder a package's source is in, or the name of an installed package:

pkg load devtools
devtools.dialectLint ('probe.m')
devtools.dialectLint ('statistics')

It reports every file that is not written in Octave's own dialect, with the line that first departs from it:

      1  dialect-octave  probe.m
         x = 1;  % a MATLAB comment

  dialect-octave  1
  total           1 of 1 files

Octave's own dialect is # comments, ! and !=, and the typed block terminators, endif, endfor, endfunction and the rest. Two spellings have no Octave alternative and are accepted: ~ for an ignored output, and %! opening a test block. A file that passes is one MATLAB cannot read, which is the point.

Would MATLAB accept it?

Ask about MATLAB instead:

devtools.dialectLint ('octprobe.m', 'matlab')

      2  dialect-matlab  octprobe.m
         x += 2;  # Octave only

  dialect-matlab  1
  total           1 of 1 files

MATLAB's dialect is % comments, ~ and ~=, and a bare end. Refused are the constructs only Octave has, among them do ... until, unwind_protect, compound assignment such as +=, ++, an index chained onto a call, and an assignment used as an expression.

This is the check to run on a script before you send it to a MATLAB machine, where Octave-only syntax fails with a message that names nothing useful. A file that passes prints one line naming it:

devtools.dialectLint: probe.m is readable by MATLAB.

A broken file is not a dialect question

Each file is read twice. If it does not parse at all, the finding is syntax, a fault the file has whichever dialect you ask about. Only a file that parses but uses the wrong dialect is reported as dialect-octave or dialect-matlab.

Findings as data

With an output argument it prints nothing and returns one element per file found, with file, line, column, rule and message, the message being the line that stopped the parse:

R = devtools.dialectLint ('octprobe.m', 'matlab');
disp (R)
    file = octprobe.m
    line = 2
    column = 3
    rule = dialect-matlab
    message = x += 2;  # Octave only

Unlike devtools.docLint, it reads private folders too: documentation obligations stop at a private helper, dialect rules do not.

What it needs

A C++ compiler when the package is installed: the files are read by a parser built at install time. Without one it raises an error saying so, rather than reporting a file clean because nothing read it.
